# 🤖 Agentic Debt Collection Workflow (MVP 2)

**Мультиагентная система для автономного ведения диалогов с должниками с гарантией соблюдения 230-ФЗ.**

---

## 🎯 Бизнес-контекст

Банки и коллекшен-агентства тратят миллиарды на операторов контакт-центра, которые ведут типовые диалоги с должниками. Одна ошибка оператора (угроза, раскрытие информации третьим лицам, звонок в нерабочее время) — это штраф от ЦБ РФ до **500 млн рублей** по 230-ФЗ.

**Проблема:** Человеческий фактор. Операторы устают, ошибаются, нарушают закон.

**Решение:** Автономная мультиагентная система, которая:
- Ведёт диалоги с должниками **24/7**
- **Физически не может нарушить 230-ФЗ** благодаря архитектурным guardrails
- Передаёт диалог человеку только в критических точках (human handoff)

---

## 🏗️ Архитектура: Multi-Agent System с Compliance Guardrails

Система построена по принципу **Tool-Mediated State Machine** с разделением ответственности.

### 4 Агента с чётким разделением ролей

**1. 🎭 Orchestrator Agent** — дирижёр системы
- Управляет State Machine (переходами между состояниями)
- Координирует работу всех агентов
- Принимает финальные решения о передаче оператору

**2. 💬 Negotiation Agent** — переговорщик
- Генерирует реплики для должника на основе состояния диалога
- Предлагает варианты реструктуризации
- **НЕ имеет доступа** к SMS-шлюзу или телефонии (принцип наименьших привилегий)

**3. 🔒 Compliance Agent** — страж закона
- Проверяет каждое действие перед исполнением
- Блокирует нарушения 230-ФЗ (время, частота, содержание)
- Работает на двух уровнях: программные проверки + LLM-валидация

**4. ⚡ Executor Agent** (в продакшене)
- Выполняет только одобренные Compliance действия
- Отправляет SMS, инициирует звонки
- Логирует все действия для аудита

### State Machine: Детерминированное управление диалогом

Диалог проходит через 8 состояний:

```
INITIATION → IDENTITY_VERIFICATION → DEBT_PRESENTATION → NEGOTIATION → PROMISE_TO_PAY → COMPLETED
```

**Ключевой принцип:** Агент физически не может "перепрыгнуть" состояние. Например, он не может перейти к переговорам без подтверждения личности.

## 🚀 Технологический стек

- **Python 3.11+**, `asyncio` (асинхронная обработка)
- **Pydantic V2** (строгая типизация данных)
- **YandexGPT** (генерация реплик и compliance-проверки)
- **Tenacity** (retry-логика с экспоненциальным backoff)
- **FastAPI** (для API-эндпоинтов в продакшене)

## 🔒 Безопасность и Compliance

### Архитектурные гарантии (не на уровне промптов!)

1. **State Machine:** Физически невозможны переходы вне заданной логики
2. **Принцип наименьших привилегий:** Negotiation Agent не имеет доступа к каналам связи
3. **Tool-Mediated Execution:** Все действия проходят через Compliance Agent
4. **Детерминированные проверки:** Время контакта, частота, содержание проверяются программно + LLM

### Что проверяет Compliance Agent

- ✅ **Время контакта** (Ст. 7 230-ФЗ): будни 08:00-22:00, выходные 09:00-20:00
- ✅ **Частота контактов** (Ст. 6 230-ФЗ): не чаще 1 раза в сутки, 2 раз в неделю, 8 раз в месяц
- ✅ **Содержание** (Ст. 5 230-ФЗ): отсутствие угроз, давления, раскрытия информации третьим лицам

## 🎯 Ключевые метрики (для продакшена)

| 📊 Метрика | Целевое значение | Описание |
| :--- | :---: | :--- |
| **Success Rate** | `> 60%` | Процент диалогов, завершившихся обещанием платежа (`promise_to_pay`) |
| **Compliance Violations** | `0` | Количество заблокированных нарушений 230-ФЗ (должно быть равно нулю) |
| **Human Handoff Rate** | `< 20%` | Процент диалогов, переданных живому оператору (human handoff) |
| **P95 Latency** | `< 3 сек` | 95-й перцентиль времени ответа агента (если больше — клиент вешает трубку) |
| **Cost per Dialogue** | `< $0.15` | Стоимость одного диалога (LLM + инфраструктура + SMS) |
